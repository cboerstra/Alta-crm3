# Alta Mortgage CRM — Integrated Advertising & Funnel System

The CRM is the control center for Facebook and Instagram advertising. A campaign
lives in one record that ties together budget, creative, a branded landing page,
the Meta objects that run the ads, and the follow-up sequence that works the
leads. Attribution is captured on every lead at first touch, so six months later
you can point at a closed loan and name the ad that produced it.

---

## The loop

```
Facebook / Instagram ad
        │  destination URL carries UTM tags + Meta's {{ad.id}} macros
        ▼
Branded landing page  ──►  Meta Pixel (browser)
   built from a template      │  shared eventID
        │                     ▼
        │              Conversions API (server)
        ▼
Lead record  ──  stores source, campaign, ad set, ad, fbc/fbp, landing URL
        │
        ├──►  Nurture sequence: email → text → call task → value email
        │
        └──►  Pipeline: consultation → under contract → closed
                    │
                    └──►  Schedule / SubmitApplication / Purchase reported back
                          to Meta, so its optimizer chases closed loans
```

## Setup

### 1. Environment

| Variable | Required for | Notes |
| --- | --- | --- |
| `PUBLIC_BASE_URL` | Publishing campaigns | Public origin of this CRM, e.g. `https://crm.altamortgagegroup.net`. Ads link to `/lp/<slug>` on this domain. Set as an env var, not in the UI — a wrong value sends live ad traffic to a dead link. |

Everything else is configured in **Settings → Meta Ads**.

### 2. Meta credentials

In Meta Business Settings, create a **system user** with:

- `ads_management` and `business_management` permissions,
- access assigned to your **ad account** and the **Facebook Page** the ads run as.

Generate a long-lived token and paste it into Settings → Meta Ads, along with:

- **Ad account ID** — `act_1234567890`
- **Facebook Page ID** — the Page identity ads are published under
- **Instagram account ID** — optional; enables Instagram placements
- **Pixel ID** — from Events Manager
- **Conversions API token** — optional; the Marketing API token is reused if blank

Press **Test connection** to read the ad account back from Meta, and **Send test
event** to confirm the server-side pipe reaches Events Manager.

### 3. Safety switch

**Allow publishing campaigns to Meta** is off by default. Until it is on, every
campaign stays local: you can build, draft, attach pages and run nurture
sequences, but no ad objects are created in the ad account. Turn it on when you
are ready to spend.

## How attribution works

Ad destination URLs are generated by the CRM, never hand-written:

```
https://crm.altamortgagegroup.net/lp/weber-county-grant
  ?utm_source=facebook
  &utm_medium=paid_social
  &utm_campaign=weber-county-grant
  &meta_campaign_id={{campaign.id}}
  &meta_adset_id={{adset.id}}
  &meta_ad_id={{ad.id}}
  &meta_placement={{placement}}
```

Meta substitutes the `{{...}}` macros at delivery time. The landing page reads
them on mount, pairs them with Meta's `_fbp` / `_fbc` cookies, and stores the lot
in session storage. **First touch wins** — if a visitor arrives from an ad,
leaves, and returns directly before submitting, the ad still gets the credit.

On submit, that payload travels with the lead and is written to the lead record:

| Field group | Columns |
| --- | --- |
| Campaign link | `campaignId` |
| UTM | `utmSource`, `utmMedium`, `utmCampaign`, `utmContent`, `utmTerm` |
| Click IDs | `fbclid`, `fbc`, `fbp`, `gclid` |
| Meta hierarchy | `metaCampaignId`/`Name`, `metaAdsetId`/`Name`, `metaAdId`/`Name`, `metaPlacement` |
| Context | `landingUrl`, `referrerUrl`, `clientIpAddress`, `clientUserAgent`, `attributionCapturedAt` |

These are written once and never overwritten. The Lead Profile page shows them in
an **Attribution** card.

Campaign resolution is strongest-signal-first: the Meta campaign id is
authoritative, the landing page is next, and `utm_campaign` is the last resort
(anyone can type one into a URL).

### Pixel + Conversions API

Every conversion is reported twice on purpose:

- the **browser pixel** fires `Lead` with an `eventID`,
- the **server** posts the same event and the same `eventID` to the Conversions
  API.

Meta de-duplicates on that pair, so the conversion is counted once. When the
browser event is blocked — ad blocker, iOS tracking prevention, Safari — the
server event still lands. That redundancy is the difference between an accurate
cost-per-lead and a fictional one.

All PII sent server-side is SHA-256 hashed after normalization (email lowercased,
phone converted to E.164 digits, names stripped to letters). Raw PII never leaves
the process. Every send is logged to `meta_conversion_events` with Meta's
response, so you have a paper trail when Events Manager disagrees with the CRM.

### Downstream conversions

Moving a lead through the pipeline reports back to Meta automatically:

| Pipeline stage | Meta event |
| --- | --- |
| Consultation booked | `Schedule` |
| Under contract | `SubmitApplication` |
| Closed | `Purchase`, with the deal value |

This is what lets Meta's optimizer chase closed loans instead of form fills.

## Landing page templates

**Page Templates** holds reusable, branded starting points. Six ship with the
CRM:

| Template | Use |
| --- | --- |
| What's My Home Worth? | Address → details → contact. The Facebook-ad workhorse. |
| Down Payment Grant | County and state assistance programs. |
| Purchase Rate Quote | Quote request for purchase-intent traffic. |
| Refinance Savings Check | Retargeting for existing homeowners. |
| Webinar Registration | Pairs with the CRM's existing webinar reminders. |
| Simple Lead Capture | Clean single-screen fallback. |

Templates use `{{tokenName}}` placeholders — `{{countyName}}`, `{{grantAmount}}`,
`{{city}}` — which you fill in when stamping out a page. Built-in templates
cannot be deleted; editable copy survives deploys, while the structural fields
(step flow, conversion event) stay current with the code.

Pages created from a template go live immediately with the pixel and Conversions
API already switched on.

## Automations

A sequence is an ordered list of steps run against each enrolled lead:

| Step | Behaviour |
| --- | --- |
| Email | Sent through the connected Gmail account |
| Text message | Telnyx; **only** sent to leads who consented (10DLC) |
| Call task | Creates a task for a loan officer to work |
| Wait | Pauses before the next step |
| Move stage | Advances the lead in the pipeline |
| Notify owner | In-platform alert |

Each delay counts from the moment the previous step ran. State lives entirely in
the database, so a restart mid-sequence resumes where it left off rather than
replaying or dropping steps. A failing step is logged and skipped — one bad email
address must not wedge the rest of a nurture track. Re-enrolling a lead already
active in the same sequence is a no-op, so filling in two forms from one campaign
does not double every text.

Triggers: a campaign's landing page, any new lead, a pipeline stage, or manual
enrollment. The scheduler runs every 60 seconds alongside the existing email and
SMS reminder schedulers.

## Campaigns

Create a campaign, and in one flow you:

1. set the objective and budget (daily or lifetime — a lifetime budget requires
   an end date, because Meta rejects it otherwise),
2. pick an existing landing page **or** build one from a template,
3. write the ad creative,
4. attach a nurture sequence.

Publishing walks Meta's object chain in order — Campaign → Ad Set → Creative →
Ad — writing each id back to the CRM as it goes. If a step fails, re-running
picks up where it stopped instead of orphaning objects in the ad account.

**Everything is created paused.** Publishing makes the objects exist; a separate
"Start delivery" click makes them spend.

Mortgage ads are declared under Meta's `HOUSING` special ad category
automatically. Meta restricts targeting by age, gender, tight radiuses and most
detailed interests on those campaigns — that is a legal requirement, not a
limitation to work around.

Insights sync hourly (Meta's reporting lags a few hours anyway) and on demand
from the campaign page.

## AI campaign drafting

Describe the campaign in plain English:

> "Create a Facebook campaign for the Weber County down payment grant, targeting
> Ogden first-time buyers, $40/day"

You get back a full proposal: campaign name, objective, budget, targeting, ad
copy, a recommended landing page template with page copy, and a four-to-six step
nurture sequence — plus compliance notes to review.

Hard rules baked into every draft:

- no specific rate, APR, payment amount or approval guarantee,
- no "guaranteed approval", "no credit check", or implied government endorsement,
- grant programs say "may qualify", never "you qualify",
- housing category constraints applied regardless of what the model proposes.

The draft populates the create-campaign form. Nothing is saved until you submit,
and nothing reaches Meta until you publish.

## Unified analytics

**Marketing** joins Meta spend to CRM outcomes:

- **By campaign** — spend, leads, cost per lead, consultations, closed loans,
  cost per closed loan, revenue, ROAS.
- **By channel** — first-touch source/medium, with close rate.
- **By ad** — which creative actually produced the loans.

Spend comes from Meta's insights API; leads, consultations and closed loans come
from the CRM, matched through the attribution recorded at first touch. Leads with
no campaign appear under **Unattributed** rather than being dropped — otherwise
the totals here would not match the Leads page and neither number would be
trustworthy.

## Database

New tables: `campaigns`, `campaign_metrics`, `landing_page_templates`,
`automation_sequences`, `automation_steps`, `automation_enrollments`,
`automation_step_runs`, `tasks`, `meta_settings`, `meta_conversion_events`.

New columns on `leads` (attribution) and `landing_pages` (tracking).

Schema changes land two ways, matching the existing project convention:

- `drizzle/0020_*.sql` for a clean `pnpm db:push`,
- `runAutoMigrations()` in `server/db.ts`, which adds the columns and creates the
  tables idempotently on startup — so an existing Hostinger database picks
  everything up on the next restart with no manual step.

## Troubleshooting

**Events Manager shows nothing.** Check Settings → Meta Ads: the pixel toggle,
the pixel ID, and whether the test event succeeds. If the test event works but
real ones don't, the page may have tracking disabled on it individually.

**Conversions counted twice.** The browser and server events must share an
`eventID`. If the landing page can't reach session storage (private browsing),
the ids diverge. Check `meta_conversion_events` for the ids actually sent.

**"Publishing to Meta is turned off."** The safety switch in Settings → Meta Ads.

**"A lifetime budget requires an end date."** Meta's rule, enforced before the
API call so you get a clear message instead of a Graph API error.

**Ad rejected for the housing category.** Copy that mentions rates, payments or
approval odds will not pass. Rewrite before resubmitting.

**Spend shows zero.** Insights lag a few hours. Use "Sync insights" on the
campaign page to force a pull.
